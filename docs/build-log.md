## By design (given, not gaps)

Sessions/logs/endpoints are append-only (revoke ≠ delete); requests are decided, never edited/deleted; harness providers are toggled, never deleted; `approvedForProviders` is computed; a file's delete is `harness reset`/a commit, not an endpoint; the organisation is not deletable from the console (PRD).


### Gaps, ranked (first hour first) — items 0–8 and 9–16 are wave 4's fix list; 17–19 are recorded, not built

0. **No console UI mints a personal access token.** `harness login` needs one pasted in; if this is really missing (see header note), it blocks the CLI from ever authenticating, which is upstream of every other CLI-side item below.
1. **Inviting a person or creating a (sub-)team 422s.** `people/_invite.tsx` sends a dotted-path string where the route requires a UUID, for both `POST /v1/org-units/{id}/invites` and `POST /v1/org-units` (`parent_id`). This is likely the literal first thing a new org-admin does. Fix: for invite, switch to `POST /v1/invites {team, email}` (already built for this); for sub-team, send `parent` instead of `parent_id`.
2. **Harness-provider approve/beta/decline 422s.** This is the first line of `harness setup`'s own checklist (`engine/cli/src/commands/setup.ts:26-27`). Fix: `providers/_decide.tsx` must send `pin` and `speaks` — the CLI already does this correctly (`providers.ts:38-40`), diff the two call sites.
3. **Security group creation 422s** (blocks `setup`'s "no security group reaches you" row). Fix: `groups/_create.tsx` must send `entries: []`.
4. **Connect-vault write is malformed** (blocks getting a key into the bundled vault before a group can resolve it). Fix: add an `id` field to the form, rename `list`→`lists_secrets`, send `auth` as an object.
5. **Team-scoped harness creation 403s** (an admin's first harness for a team, not for themselves, fails). Fix: drop the `"team:"` prefix from the `POST /v1/harnesses` body's `scope`.
6. **Admin revoking someone else's session 404s**, the inverse of the product's stated rule (SESSIONS_TEXT.refusal says only an admin decides, the owner just Ctrl-Cs). Fix: authorize `revoke_session`/`broker.owned_active` by team-admin-over-owner, not only self-ownership.
7. **Visibility switch always 404s.** Fix: pass the person's org-unit id/path, not `PersonRow.id` (the auth_user_id).
8. **Removing a person 404s once their team is a nested sub-team**, because `teams.items[0]` picks the widest ancestor, not the immediate parent. Fix: have the server return (or the client compute) the person's *direct* team path, not "the first team in an alphabetically-sorted ancestor list."
9. **Appoint/revoke a team admin** has no direct console control (only reachable by accepting a role request). Wire a button on the People screen to `PUT`/`DELETE /v1/org-units/{id}/admins/{person_id}`.
10. **Group entries/sources editing** (`addEntry`, `changeSources`) declared, unwired. Wire a control on the group detail page to `PATCH /v1/groups/{name}`.
11. **Revoke a grant** declared, unwired. Wire a row action on the grants table to `DELETE /v1/grants/{id}`.
12. **Remove a boundary** declared, unwired. Wire a row action on the boundaries table to `DELETE /v1/boundaries/{id}`.
13. **Model providers tab is read-only** for anything beyond the CLI's `keys add`. `addModelProvider` declared, unwired. Wire a create/edit form to `PUT /v1/providers/model/{id}`.
14. **Approval scope isn't settable from the console** — the one modal hardcodes `scope: {"teams":"all"}`, while the CLI has `--teams`. Add a team picker to `_decide.tsx`.
15. **Rotate a vault secret** declared, unwired. Wire a row action to `POST /v1/vaults/{id}/secrets/{ref}/rotate`.
16. **Cancel a pending invite** — no verb even declared, no UI. Add a verb + wire `DELETE /v1/invites/{id}`.
