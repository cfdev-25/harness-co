=== AGENTS.md
Harness assets live at `<assetsRoot>/<kind>/<name>/` — `skill/`, `tool/`, `prompt/`, `memory/`, `system_prompt/`, `connection/`, `context/`, `environment/`. A new skill, tool, prompt, context (a template, a reference, brand assets) or environment (what must be installed) goes there, in that kind's shape; it is offered to keep when the session ends. Files in the working directory belong to the project, not to the harness. The `harness-authoring` skill says how to make one, and how to extract a setup from another tool. This harness has its own Python and Node environments, first on PATH: install there, never on the machine, and record what you install in an environment asset.

Reach: off. This session can only connect to the hosts it holds a credential for; anything else is refused by the fence, and the model may not browse on the provider's side either. acme decides this.

This harness delivers: skills quokka · prompts standup · memories release-notes · tools deploy · contexts brand-assets · environments deck-tools.

## release-notes

We ship on Thursdays.

## Tools

- `deploy` — run `<assetsRoot>/tool/deploy/run`

## Context

Read when a task calls for it; nothing here is loaded on its own.

- `brand-assets` — `<assetsRoot>/context/brand-assets/` — Colours, logos and the deck template.

## Environment

What this harness declares its environment holds. Apply what is missing, inside this session; record what you add.

- `deck-tools` — What the deck tool needs. — apply with `pip install -r <assetsRoot>/environment/deck-tools/requirements.txt`
